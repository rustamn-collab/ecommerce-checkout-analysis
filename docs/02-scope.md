# 2. Область проекта (Scope)

## 2.1. Назначение документа

Документ фиксирует границы проекта: что входит в зону ответственности команды, что остаётся за рамками, от каких внешних систем проект зависит и какие риски могут повлиять на его реализацию. Чёткое определение Scope защищает от «расползания» требований (scope creep) и помогает стейкхолдерам синхронизировать ожидания.

## 2.2. In Scope (что входит в проект)

### 2.2.1. Функциональные блоки

| Блок | Описание |
|------|----------|
| **Корзина** | Добавление, изменение, удаление товаров. Проверка остатков и цен через ERP. |
| **Расчёт доставки** | Стоимость и сроки на основе адреса, габаритов, веса, загрузки складов. |
| **Чекаут** | Выбор адреса, слота доставки, способа оплаты. Создание черновика заказа. |
| **Резервирование** | Жёсткий резерв товара на 15 минут при переходе к оплате. |
| **Сплитование заказов** | Разделение заказа на несколько отправлений при доставке с разных складов. |
| **Онлайн-оплата** | Интеграция с Payment Gateway, обработка webhook, идемпотентность. |
| **Отмена и возврат** | Отмена заказа до передачи курьеру, возврат средств при оплаченном заказе. |
| **Уведомления** | Push/SMS/email на ключевых этапах: оплата, сборка, передача курьеру. |
| **Интеграции** | ERP, WMS, Payment Gateway, курьерские службы, Kafka. |

### 2.2.2. Каналы

- Мобильное приложение (iOS, Android).
- Веб-сайт интернет-магазина (desktop, mobile web).

### 2.2.3. Технические артефакты

- Функциональные и нефункциональные требования.
- BPMN-схемы AS-IS и TO-BE.
- Sequence-диаграммы (PlantUML).
- C4-архитектура (Context, Container, Component).
- REST API-контракты (Swagger/OpenAPI).
- Модель данных (ER-диаграмма, SQL-схема).
- Схема событий Kafka.
- State Machine заказа.
- Стратегия тестирования и тест-кейсы.
- План мониторинга и алертинга.

### 2.2.4. Бизнес-процессы

- Полный цикл оформления заказа: от корзины до подтверждения оплаты.
- Альтернативные потоки: out of stock, payment failed, отмена заказа.
- Автоматическое снятие резерва по таймауту.

## 2.3. Out of Scope (что НЕ входит в проект)

### 2.3.1. Функциональные блоки

| Блок | Причина исключения |
|------|-------------------|
| **Админ-панель оператора** | Отдельный проект, не влияет на клиентский чекаут. |
| **Управление каталогом товаров** | Зона ответственности PIM-системы. |
| **Управление ценами и промо** | Зона ответственности маркетинга и прайс-системы. |
| **Программа лояльности** | Отдельный домен, интеграция — задача будущих релизов. |
| **Возврат товара после доставки** | Постпродажный процесс, не входит в чекаут. |
| **Логистика «последней мили»** | Зона ответственности курьерской службы. |
| **Управление складскими операциями** | Зона ответственности WMS. |
| **Маркетплейс (сторона поставщика)** | Отдельная платформа, интеграция — вне рамок. |
| **Мультивалютность** | Работаем только в RUB. |
| **Мультиязычность интерфейса** | Только русский язык. |

### 2.3.2. Нефункциональные аспекты вне рамок

- Миграция legacy-данных.
- Обучение операторов клиентского сервиса.
- Разработка дизайна UI/UX.
- Проведение маркетинговых кампаний.
- Юридическая экспертиза договоров с курьерскими службами.

## 2.4. Зависимости

### 2.4.1. Внутренние системы

| Система | Роль | Критичность |
|---------|------|-------------|
| **ERP System** | Источник истины по остаткам и ценам | Высокая |
| **WMS** | Управление складскими операциями | Высокая |
| **API Gateway** | Единая точка входа | Высокая |
| **Kafka** | Шина событий | Высокая |
| **Notification Service** | Push/SMS/email | Средняя |
| **Analytics Platform** | Сбор данных для BI | Низкая |
| **Auth Service** | Аутентификация пользователей | Высокая |

### 2.4.2. Внешние системы

| Система | Роль | SLA |
|---------|------|-----|
| **Payment Gateway** | Онлайн-оплата, возврат | 99,9% |
| **Courier Services API** | Передача заказа, трекинг | 99,5% |
| **SMS-провайдер** | SMS-уведомления | 99,0% |
| **Push-провайдер (FCM/APNS)** | Push-уведомления | 99,5% |

### 2.4.3. Команды и роли

| Роль | Ответственность |
|------|-----------------|
| Product Owner | Приоритизация бэклога |
| Системный аналитик | Требования, API, модель данных, интеграции |
| Backend-разработчики | Микросервисы чекаута, корзины, логистики |
| Frontend-разработчики | Мобильное приложение, сайт |
| QA-инженеры | Тестирование, UAT |
| DevOps | CI/CD, мониторинг, инфраструктура |
| Архитектор | Архитектурные решения, ревью |

## 2.5. Ограничения проекта

| № | Ограничение | Влияние |
|---|-------------|---------|
| 1 | ERP-система не может быть изменена | Работаем только с существующими API |
| 2 | Payment Gateway — внешний | Не контролируем SLA и логику |
| 3 | Микросервисная архитектура | Дополнительная сложность в интеграциях |
| 4 | Единый API для мобильного и веб | Учёт особенностей обоих каналов |
| 5 | Срок релиза — 6 месяцев | Жёсткие дедлайны этапов |
| 6 | Команда распределённая | Асинхронная коммуникация |

## 2.6. Допущения

| № | Допущение |
|---|-----------|
| 1 | ERP выдерживает нагрузку до 500 RPS на чтение остатков |
| 2 | Payment Gateway поддерживает идемпотентность через Idempotency-Key |
| 3 | Kafka гарантирует at-least-once доставку |
| 4 | Пиковая нагрузка — 10 000 одновременных пользователей |
| 5 | Поток событий — до 50 000 сообщений в сутки |
| 6 | Средний чек — 5 000 ₽ |
| 7 | Доля крупногабаритных товаров — 15% |

## 2.7. Критерии успеха проекта

| Критерий | Метрика |
|----------|---------|
| Конверсия корзины | +7% к базовой |
| Отмены из-за out of stock | -15% |
| Обращения в клиентский сервис по доставке | -25% |
| Время оформления заказа (p95) | ≤ 5 сек |
| Доступность чекаута | 99,95% |
| Дубли заказов при оплате | 0 |
| Покрытие интеграций тестами | ≥ 80% |

## 2.8. Риски на уровне Scope

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Расширение требований в процессе | Высокая | Высокое | Change Request, ревью с PO |
| Недоступность ERP в пик | Средняя | Высокое | Кэширование, Circuit Breaker |
| Изменение API платёжного шлюза | Низкая | Высокое | Версионирование, контрактные тесты |
| Задержка релиза из-за интеграций | Средняя | Среднее | Раннее тестирование, mock-сервисы |
| Рост нагрузки выше допущений | Средняя | Среднее | Нагрузочное тестирование, автомасштабирование |
